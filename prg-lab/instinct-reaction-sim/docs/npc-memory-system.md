# NPC Memory System

NPC Memory System は、周辺NPCを一時的な背景ではなく、説得、雇用、同行、再会によって変化する存在として扱うための設計メモです。

## 基本方針

その辺にいるNPCも、プレイヤーとの接触によって履歴を持ちます。

プレイヤーはNPCを説得したり、雇用したり、一時的に同行させたりできます。同行が終わったあとも、そのNPCは経験ログや感情変化を保持し、再会時の反応や同行条件に影響します。

## 説得・雇用・同行

NPCに対して将来的に扱いたい行動:

- 説得する
- 雇用する
- 仲間として同行させる
- 一時的な案内役にする
- 戦闘や探索を手伝わせる
- 途中で解散する
- 見捨てる、裏切る、守る

このプロトタイプではまだ実装せず、将来の Behavior Policy / Relationship Memory の入力候補として整理します。

## 解散後の経験ログ

NPCは同行終了後も経験ログを保持します。

記録候補:

- 同行した期間
- 一緒に訪れた場所
- 戦闘や危険を経験した回数
- プレイヤーに助けられた経験
- プレイヤーに見捨てられた経験
- 報酬や約束が守られたか
- 解散時の状態

経験ログは、再会時の態度や将来の関係変化に使います。

## 関係による感情変化

NPCはプレイヤーとの関係に応じて、内部状態が変化します。

主な値:

- 信頼
- 不満
- 愛着
- 恐怖
- 尊敬
- 警戒
- 依存

同じ「同行する」でも、信頼して同行するのか、報酬目的なのか、恐怖で従っているのかによって、その後の行動が変わります。

## 再会時の反応変化

再会時には、過去の関係と経験ログをもとに反応を変えます。

例:

- 信頼が高いNPCは自発的に協力する
- 不満が高いNPCは報酬を要求する
- 恐怖が高いNPCは逃げる、または従う
- 愛着が高いNPCは再同行を望む
- 裏切られたNPCは拒絶や敵対を選ぶ
- 過去に守られたNPCは情報提供する

同行条件も固定ではなく、関係や記憶によって変化します。

## 将来のデータ候補

```json
{
  "npc_id": "npc_001",
  "name": "村人A",
  "trust": 0.5,
  "frustration": 0.1,
  "attachment": 0.2,
  "fear": 0.0,
  "shared_experience_log": [
    "森の入口まで同行した",
    "狼との戦闘で守られた"
  ],
  "memory_summary": "プレイヤーに助けられたため、再会時にやや協力的。",
  "companion_policy": "conditional"
}
```

この設計は、MPER の runtime_state、relationship memory、growth log と接続する想定です。
