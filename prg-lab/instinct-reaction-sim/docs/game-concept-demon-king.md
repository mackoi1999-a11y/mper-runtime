# Game Concept: Demon King

このメモは、PRG / MPER Runtime を使ったゲーム方向性の初期コンセプトです。

## 最終目的

最終目的は魔王討伐です。

ただし、プレイヤーが誰と、どのように、どんな関係を築きながら攻略するかは固定しません。

## 自由な攻略

魔王討伐までの道筋は、プレイヤーごとに変わります。

例:

- 村人を説得して同行者にする
- 雇ったNPCと旅をする
- 敵を見逃して後の因縁を作る
- 逃げ延びた敵が再登場する
- NPCとの信頼関係で攻略ルートが変わる
- 敵対者を交渉で味方にする
- 途中で仲間と別れる

攻略の自由度は、マップ分岐だけでなく、キャラクターの履歴と関係性によって生まれます。

## モブNPCも履歴を持つ

モブNPCも、プレイヤーとの接触によって記憶を持ちます。

例:

- 助けられた村人が後で協力する
- 雇われたNPCが経験を積む
- 見捨てられたNPCが不信感を持つ
- 長く同行したNPCが愛着を持つ
- 恐怖で従っていたNPCが離反する

これにより、単なる背景NPCがプレイヤー固有の物語に参加します。

## 敵も履歴を持つ

敵も、倒されなければ記憶と成長を持ちます。

例:

- 逃げた敵が再登場する
- プレイヤーを恐れて逃げやすくなる
- 復讐心を持って待ち伏せする
- 何度も逃がすと名前付きになる
- 中ボス化して地域の脅威になる

敵を倒すか、逃がすか、交渉するかが、後の世界状態に影響します。

## プレイヤー固有の物語

このコンセプトの中心は、固定シナリオだけではなく、履歴から生まれるプレイヤー固有の物語です。

同じ魔王討伐でも、あるプレイヤーは村人たちと協力して進み、別のプレイヤーは敵との因縁を重ねながら進むかもしれません。

PRG / MPER Runtime は、その差分を以下の形で支えます。

- Runtime State
- Growth Log
- Persistent Enemy Memory
- NPC Memory
- Relationship Memory
- Behavior Policy
- Memory Summary

最終的には、魔王討伐という共通目的に向かいながら、そこに至る関係性と履歴がプレイヤーごとに異なるゲーム体験を作ります。
